# C42 / C15 Defect Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix C42 (RealTimeScheduler lacks the C36 id-publish/self-join discipline, so a ProcessingUnit task calling `stop()` still silently escalates to FATAL_ERROR — C40's symptom from the framework's primary user extension point) plus the parked `~AxonVexSystem` lifetime-contract docs item, and C15 (Path: broken DCLP on static init, substr underflow in createConfigPath/createLogPath, substring-based traversal check with false positives, unlocked whitelist iteration).

**Architecture:** C42 extends the batch-4 refusal mechanism one thread family further: `RealTimeScheduler` publishes its worker id (RAII, the C36 pattern), gains a self-join guard in `stop()`, and `AxonVexSystem::isOnWorkerThread()` consults it through a `TimingController` forwarding accessor — so `initialize()`/`stop()`/`reset()`'s existing refusals now cover task bodies too. C15 replaces the broken double-checked lock with a C++11 magic static, adds length guards, makes the traversal check component-based, and documents/locks the whitelist iteration.

**Tech Stack:** C++14, GoogleTest/CTest, ASan/UBSan/TSan sanitizer builds.

## Global Constraints

- **C++14 strictly.** No C++17-isms.
- **Zero-warning policy.** No new dependencies.
- **No sleep-based test synchronization** — poll an atomic against a `steady_clock` deadline; no `condition_variable::wait_for` in tests.
- **TSan mandatory for Task 1** (thread lifecycle). Task 2: full suite + ASan on PathTest; TSan run of PathTest as a sanity pass.
- **Thread-teardown checklist** (4 prior CRITICALs): (1) can a user callback re-enter this? (2) two threads inside at once? (3) self-check must read ids the WORKER publishes, never `thread_.get_id()`; (4) self-check BEFORE any mutex the joiner holds; (5) destructor detach fallback for self-destroy; (6) what did any deleted guard also protect?
- **Test gate for lifecycle tests:** serial green is insufficient — run the new/coupled lifecycle tests under parallel load (6 concurrent processes × ≥6 repeats each) before claiming done; this gate caught two flakes last batch that 30/30 serial runs missed.
- Build/test commands (dirs configured; NEVER run conan or cmake configure):
  - `cmake --build build -j$(nproc)` then `ctest --test-dir build --output-on-failure`
  - ASan: `cmake --build build-asan -j$(nproc)` then `ctest --test-dir build-asan --output-on-failure -R <filter>`
  - TSan: `cmake --build build-tsan -j$(nproc)` then `setarch $(uname -m) -R ctest --test-dir build-tsan --output-on-failure -R <filter>`
  - Known flakes (rerun once): `TimingControllerTest.SchedulerPauseAndResume`, `PrecisionTimerTest.PerformanceTest`; TSan perf-threshold tests.
- `clang-format -i` touched files. Defect ID in commit messages. Plan §3 rows: SYMBOL references + Status paragraph + CHANGELOG, same commit.

### Task 2: C15 — Path: broken DCLP, substr underflow, substring traversal check, unlocked whitelist iteration

**Files:**
- Modify: `src/libs/axonvex_core/src/path.cpp`:
  - the three ctors' broken DCLP (`initialized_` plain bool checked outside `static_mutex_`, path.cpp ~76-103) → one `ensureInitialized()` helper using a C++11 magic static
  - `createConfigPath` (~748) and `createLogPath` (~764): `filename.substr(filename.length() - N)` underflows for names shorter than the extension → guard with a length check
  - `hasDirectoryTraversal()` (~793): substring scan flags "my..file" and "./" (false positives) — replace with a component-based check (traversal iff a component is exactly `".."`)
  - `isInWhitelist()` (~811): iterates `default_dirs_` unlocked — after the magic-static fix, verify NOTHING mutates `default_dirs_` post-init (grep all writers; `initializeDefaultDirs` must be the only one). If immutable-after-init holds, document that as the safety argument at the member; if any post-init writer exists, lock `static_mutex_` around the iteration instead.
- Modify: `src/libs/axonvex_core/include/axonvex_core/path.hpp` (declarations the above need; remove `initialized_` if fully replaced)
- Test: `tests/core/pathTest.cpp` (exists)

**Interfaces:**
- Consumes: nothing from Task 1.
- Produces: no signature changes. Behavior changes: short names no longer throw from `createConfigPath`/`createLogPath` (extension appended); paths containing ".." as a substring of a component (e.g. `my..file.json`) or a `./` prefix are no longer flagged as traversal; genuine `..` components still are. Label both as behavior changes in the CHANGELOG.

**Defect (plan §3 row C15):** four shapes. (a) `Path::Path(...)` ctors check `initialized_` (plain bool) before taking `static_mutex_` — broken double-checked locking: a racing second thread can see `initialized_ == true` while `default_dirs_`'s writes are not yet visible. (b) `createConfigPath("a")` → `filename.length() - 5` underflows size_t → `substr` throws `std::out_of_range`. (c) `hasDirectoryTraversal` substring-matches `".."`/`"./"`/`".\\"` — false positives on legitimate names; the component check is exact. (d) `isInWhitelist` iterates static shared state unlocked.

**Security note (trust boundary — do not weaken):** the traversal check's job is rejecting escape attempts. The component-based replacement must flag every path with a real `..` component — `"a/../b"`, `".."`, `"../x"`, and Windows-separator forms if the compat layer produces them. Add positive AND negative tests.

- [ ] **Step 3: Implement**

(a) Replace the three ctors' DCLP with one helper:

```cpp
void Path::ensureInitialized() {
    // C15: replaces broken double-checked locking (plain-bool check outside
    // the mutex). C++11 magic statics give a thread-safe once-guard.
    static const bool once = []() {
        initializeDefaultDirs();
        return true;
    }();
    (void)once;
}
```

Each ctor calls `ensureInitialized();`. Delete `initialized_` (and its declaration) if nothing else reads it; before touching `static_mutex_`, check its remaining users (checklist item 6).

bool Path::hasDirectoryTraversal() const {
