**Goal:** Fix the next three HIGH defects from `docs/v1_release_plan.md` §3: C5 (Configuration::applyUpdates UB + callback deadlock), C7 (state-machine bypass + double initializeComponents), C9 (cross-system connect AB/BA deadlock).

**Architecture:** All three are concurrency-contract fixes in `axonvex_core`, each following the project's established snapshot-then-dispatch / validated-transition patterns. No new files, no new dependencies; each task is one defect with its regression tests.

**Tech Stack:** C++14, GoogleTest/CTest, ASan/UBSan/TSan sanitizer builds.

## Global Constraints

- **C++14 strictly.** No `std::optional`, `std::filesystem`, structured bindings, `if constexpr`. (`std::lock(a, b)` and `std::unique_lock` are C++11 — fine.)
- **Never invoke user callbacks while holding a lock.** Snapshot under the lock, release, then dispatch (CLAUDE.md architecture rule 3).
- **Zero-warning policy** — new warnings = broken build.
- **No sleep-based test synchronization.** Poll an atomic against a `steady_clock` deadline. Do NOT use `condition_variable::wait_for` in tests — GCC 11's libtsan does not intercept `pthread_cond_clockwait` and reports bogus races.
- **TSan is mandatory** for every task here (all touch threads/locks/callbacks).
- Build/test commands (build dirs already configured, no conan needed):
  - `cmake --build build -j$(nproc)` then `ctest --test-dir build --output-on-failure`

  - Known load-sensitive flakes (rerun once before believing a failure): `TimingControllerTest.SchedulerPauseAndResume`, `PrecisionTimerTest.PerformanceTest`.
- Run `clang-format -i` on touched files before committing. Reference the defect ID (C5/C7/C9) in each commit message.
- Naming: methods/variables `camelCase`, members trailing underscore. `configuration.cpp` locally uses `snake_case` members (`config_mutex_`, `callbacks_mutex_`) — match the file you're in.

### Task 1: C5 — Configuration::applyUpdates mid-merge unlock (UAF) + callbacks invoked under callbacks_mutex_ (deadlock)

**Files:**
- Modify: `src/libs/axonvex_core/src/configuration.cpp` (`applyUpdates` ~line 329, `notifyCallbacks` ~line 577)
- Test: `tests/core/configurationTest.cpp` — **three regression tests already exist uncommitted in the working tree** (`CallbackMayMutateConfigDuringUpdateNotification`, `CallbackMayReenterCallbackRegistration`, `ConcurrentUpdatesAndWritesAreRaceFree`), written test-first by a prior session. Do not rewrite them; read them — they specify the contract.
- Modify: `.gitignore` — add `test_trace.txt`; also delete the stray untracked `test_trace.txt` at repo root.

**Interfaces:**
- Consumes: existing `Configuration` public API (unchanged).
- Produces: no signature changes. New contract: callbacks are invoked after the update is fully merged, with no Configuration lock held; a callback may freely call `set`/`remove`/`registerCallback`/`unregisterCallback`. An `unregisterCallback` racing a notification may still see one in-flight invocation (snapshot semantics — same as the C12/C18/C34 fixes).

**Defect (from plan §3 + source):** `applyUpdates` holds `config_mutex_` and runs a recursive merge lambda holding live `nlohmann::json` references into `config_data_`; for each changed leaf it does `lock.unlock(); notifyCallbacks(...); lock.lock();` mid-merge. Any concurrent writer — or the callback itself — can mutate/destroy the referenced nodes; the merge resumes writing through dangling references (heap-use-after-free). Separately, `notifyCallbacks` invokes user callbacks while holding `callbacks_mutex_`, so a callback touching `registerCallback`/`unregisterCallback` deadlocks a non-recursive mutex.

- [ ] **Step 2: Fix `applyUpdates` — merge fully under the lock, notify after**

Replace the body of `Configuration::applyUpdates`:

```cpp
bool Configuration::applyUpdates(const nlohmann::json& updates, bool validate) {
    // C5: collect changes under the lock, notify after releasing it. The old
    // code unlocked mid-merge while the recursive lambda held json references
    // into config_data_; a concurrent writer or the callback itself could
    // destroy the referenced nodes and the merge resumed through them (UAF).
    std::vector<std::tuple<std::string, ConfigValue, ConfigValue>> changes;
    {
        std::unique_lock<std::shared_timed_mutex> lock(config_mutex_);
        try {
            // Validate updates if requested
            if (validate && validation_enabled_.load(relaxed)) {
                auto errors = validateInternal(updates);
                if (!errors.empty()) {
                    stats_.validation_failures.fetch_add(1, relaxed);
                    return false;
                }
            }

            // Apply updates recursively
            std::function<void(nlohmann::json&, const nlohmann::json&, const std::string&)>
                merge = [&](nlohmann::json& target, const nlohmann::json& source,
                            const std::string& prefix) {
                    for (auto it = source.begin(); it != source.end(); ++it) {
                        std::string full_key =
                            prefix.empty() ? it.key() : prefix + "." + it.key();

                        if (it->is_object() && target.contains(it.key()) &&
                            target[it.key()].is_object()) {
                            merge(target[it.key()], *it, full_key);
                        } else {
                            ConfigValue old_value;
                            if (target.contains(it.key())) {
                                old_value = target[it.key()];
                            }
                            target[it.key()] = *it;
                            if (monitoring_enabled_.load(relaxed)) {
                                changes.emplace_back(full_key, std::move(old_value), *it);
                            }
                        }
                    }
                };

            merge(config_data_, updates, "");
            stats_.total_updates.fetch_add(1, relaxed);
            stats_.runtime_updates.fetch_add(1, relaxed);
        } catch (const std::exception&) { return false; }
    }

    for (const auto& change : changes) {
        notifyCallbacks(std::get<0>(change), std::get<1>(change), std::get<2>(change));
    }
    return true;
}
```

- [ ] **Step 3: Fix `notifyCallbacks` — snapshot matching callbacks, invoke unlocked**

Replace the body of `Configuration::notifyCallbacks`:

```cpp
void Configuration::notifyCallbacks(const std::string& key, const ConfigValue& old_value,
                                    const ConfigValue& new_value) {
    // C5: snapshot under the lock, invoke unlocked, so a callback may call
    // registerCallback/unregisterCallback (both take callbacks_mutex_) without
    // deadlocking. An unregister racing a notification may still see one
    // in-flight invocation — inherent to snapshot-then-dispatch.
    std::vector<ConfigurationCallback> matched;
    {
        std::lock_guard<std::mutex> lock(const_cast<std::mutex&>(callbacks_mutex_));
        for (const auto& pair : callbacks_) {
            if (matchesPattern(key, pair.second.first)) {
                matched.push_back(pair.second.second);
            }
        }
    }

    for (const auto& callback : matched) {
        try {
            callback(key, old_value, new_value);
            stats_.callback_invocations.fetch_add(1, relaxed);
        } catch (const std::exception&) {
            // Ignore callback exceptions
        }
    }
}
```

### Task 2: C7 — state-machine bypass in emergencyShutdown/reset + double initializeComponents in initialize()

**Files:**
- Modify: `src/libs/axonvex_core/src/system.cpp`:
  - `transitionState` (~line 1073): make FATAL_ERROR legal from any state
  - `emergencyShutdown` (~line 464): route through `transitionState`
  - `reset` (~line 566): route through `transitionState`
  - `initialize(const std::string&)` (~line 198): delete the second `initializeComponents()` call and its `drainEventQueue()` prelude (~lines 221–230)
- Test: `tests/core/systemTest.cpp` (fixture `AxonVexSystemTest`, helper `TestAxonVexSystem` already exist)

**Interfaces:**
- Consumes: `AxonVexSystem::transitionState`, `getStatistics()` (`SystemStatistics.totalStateTransitions` is `std::atomic<uint64_t>`, system.hpp:122).
- Produces: no signature changes. New contract: every state change — including e-stop and reset — goes through `transitionState` and is counted in `totalStateTransitions` and published as a STATE_CHANGE event when the event thread is alive; `newState == FATAL_ERROR` is a valid transition from every state.

**Defect (from plan §3 + source):** `emergencyShutdown` (system.cpp:465) and `reset` (system.cpp:573) write `currentState_.store(...)` directly, skipping `transitionState`'s validation/statistics/logging/notification; `initialize()` calls `initializeComponents()` twice (lines 200 and 226) — the second call rebuilds every component identically (they are configured from `systemConfig_`, which `loadConfiguration` never touches — it only fills `configuration_`), and the rebuild is what forced the C25 `drainEventQueue()` workaround (pool replaced while the INITIALIZING event lived in it).

**Context you need:** `notifyStateChange` only builds a `SystemEvent` and calls `publishEvent` (enqueue; no user callbacks run under `stateMutex_` — the C18 fix moved dispatch to the event thread). `publishEvent` drops events once `isShuttingDown_` is true — so in `emergencyShutdown`, call `transitionState(FATAL_ERROR)` BEFORE `isShuttingDown_.store(true)`. The existing `notifyStateChange(oldState, SystemState::FATAL_ERROR)` at ~line 516 has been dead (always dropped) for this reason — remove it, `transitionState` now does it.

**Trap this change opens:** `publishEvent` (~system.cpp:1387) dereferences `eventPool_`/`eventQueue_` with NO null guard. Pre-fix, `emergencyShutdown` on a never-initialized system was safe only because `isShuttingDown_` was set before the (dead) notify. Post-fix, `transitionState(FATAL_ERROR)` runs first → `notifyStateChange` → `publishEvent` → null `eventPool_` → segfault on `TestAxonVexSystem s; s.emergencyShutdown();`. Add the null guard to `publishEvent` (same style as `drainEventQueue`'s guard):

```cpp
    // Components may not exist yet (e-stop on a never-initialized system).
    if (!eventPool_ || !eventQueue_) {
        return;
    }
```

### Task 3: C9 — connectToSystem/disconnectFromSystem AB/BA deadlock

**Files:**
- Modify: `src/libs/axonvex_core/include/axonvex_core/system.hpp` (`connectToSystem` ~line 812, `disconnectFromSystem` ~line 871, both template implementations at the bottom of the header; add one private helper near the port-management private section)
- Test: `tests/core/systemTest.cpp`

**Interfaces:**
- Consumes: `MockProcessingUnit` in systemTest.cpp (has `OutputPort<double>` id 1000 named "test_output", `InputPort<double>` id 1001 named "test_input"); `assignSystemOutputPort/assignSystemInputPort(name, unit, portId)`.
- Produces: no signature changes. New contract: `a.connectToSystem<T>(..., &b, ...)` concurrent with `b.connectToSystem<T>(..., &a, ...)` cannot deadlock; `targetSystem == this` (self-connection) is supported instead of locking the same mutex twice (UB).

**Defect (from plan §3 + source):** both functions do `lock_guard lock1(systemPortsMutex_); lock_guard lock2(targetSystem->systemPortsMutex_);` — argument order. Thread 1 running `a.connectToSystem(&b)` and thread 2 running `b.connectToSystem(&a)` acquire the two mutexes in opposite orders: classic AB/BA deadlock. Bonus: `a.connectToSystem(&a)` locks the same non-recursive mutex twice — UB.

- [ ] **Step 1: Write the failing tests**

Append to `tests/core/systemTest.cpp` (system-port section). Deadline-guard pattern: polled atomics + detach-on-wedge (a regression hangs rather than fails; no condition_variable — TSan false positives).

```cpp
namespace {
// Registers a MockProcessingUnit on `sys` and exposes its ports as system
// ports "out"/"in". Returns false on any setup failure.
bool exposeSystemPorts(AxonVexSystem& sys) {
    auto unit = std::make_unique<MockProcessingUnit>("PortUnit");
    MockProcessingUnit* unitPtr = unit.get();
    sys.registerProcessingUnit(std::move(unit));
    return sys.assignSystemOutputPort("out", unitPtr, 1000) &&
           sys.assignSystemInputPort("in", unitPtr, 1001);
}
} // namespace

// C9 regression: connectToSystem/disconnectFromSystem locked the two systems'
// systemPortsMutex_ in ARGUMENT order, so a→b concurrent with b→a acquired
// them in opposite orders — AB/BA deadlock. Deadline-guarded: a regression
// hangs rather than fails.
TEST_F(AxonVexSystemTest, OpposingCrossSystemConnectsDoNotDeadlock) {
    TestAxonVexSystem a, b;
    ASSERT_TRUE(a.initialize());
    ASSERT_TRUE(b.initialize());
    ASSERT_TRUE(exposeSystemPorts(a));
    ASSERT_TRUE(exposeSystemPorts(b));

    auto doneA = std::make_shared<std::atomic<bool>>(false);
    auto doneB = std::make_shared<std::atomic<bool>>(false);

    std::thread ta([&a, &b, doneA]() {
        for (int i = 0; i < 500; ++i) {
            a.connectToSystem<double>("out", &b, "in");
            a.disconnectFromSystem<double>("out", &b, "in");
        }
        doneA->store(true);
    });
    std::thread tb([&a, &b, doneB]() {
        for (int i = 0; i < 500; ++i) {
            b.connectToSystem<double>("out", &a, "in");
            b.disconnectFromSystem<double>("out", &a, "in");
        }
        doneB->store(true);
    });

    const auto deadline = std::chrono::steady_clock::now() + std::chrono::seconds(20);
    while (!(doneA->load() && doneB->load()) &&
           std::chrono::steady_clock::now() < deadline) {
        std::this_thread::sleep_for(std::chrono::milliseconds(1));
    }
    if (!doneA->load() || !doneB->load()) {
        ta.detach(); // wedged; leak them rather than hang the suite
        tb.detach();
        FAIL() << "opposing cross-system connects deadlocked";
    }
    ta.join();
    tb.join();
}

// C9, second shape: targetSystem == this locked the same non-recursive mutex
// twice (UB, hangs in practice). Self-connection is legitimate — an output
// port looped back to an input port of the same system.
TEST_F(AxonVexSystemTest, ConnectSystemToItselfDoesNotSelfDeadlock) {
    TestAxonVexSystem a;
    ASSERT_TRUE(a.initialize());
    ASSERT_TRUE(exposeSystemPorts(a));

    auto done = std::make_shared<std::atomic<bool>>(false);
    auto connected = std::make_shared<std::atomic<bool>>(false);
    std::thread worker([&a, done, connected]() {
        connected->store(a.connectToSystem<double>("out", &a, "in"));
        a.disconnectFromSystem<double>("out", &a, "in");
        done->store(true);
    });

    const auto deadline = std::chrono::steady_clock::now() + std::chrono::seconds(10);
    while (!done->load() && std::chrono::steady_clock::now() < deadline) {
        std::this_thread::sleep_for(std::chrono::milliseconds(1));
    }
    if (!done->load()) {
        worker.detach();
        FAIL() << "self-connection deadlocked on systemPortsMutex_";
    }
    worker.join();
    EXPECT_TRUE(connected->load());
}
```

- [ ] **Step 3: Implement the deadlock-free lock helper and use it in both functions**

Add a private member function to `AxonVexSystem` (near the port-management private section in system.hpp):

```cpp
    /**
     * C9: acquires this system's and the target's systemPortsMutex_ without a
     * lock-order deadlock (std::lock), and locks only once when target == this
     * (locking a non-recursive mutex twice is UB). Second lock is empty in the
     * self case.
     */
    std::pair<std::unique_lock<std::mutex>, std::unique_lock<std::mutex>>
    lockSystemPortsWith(AxonVexSystem* targetSystem) {
        std::unique_lock<std::mutex> lock1(systemPortsMutex_, std::defer_lock);
        std::unique_lock<std::mutex> lock2;
        if (targetSystem == this) {
            lock1.lock();
        } else {
            lock2 = std::unique_lock<std::mutex>(targetSystem->systemPortsMutex_,
                                                 std::defer_lock);
            std::lock(lock1, lock2);
        }
        return std::make_pair(std::move(lock1), std::move(lock2));
    }
```

In BOTH `connectToSystem` and `disconnectFromSystem`, replace:

```cpp
    std::lock_guard<std::mutex> lock1(systemPortsMutex_);
    std::lock_guard<std::mutex> lock2(targetSystem->systemPortsMutex_);
```

with:

```cpp
    auto portLocks = lockSystemPortsWith(targetSystem);
```

(`<utility>` for `std::pair` is already transitively available; add the include only if the build says otherwise.)
