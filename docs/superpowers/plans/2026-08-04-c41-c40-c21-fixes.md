# C41 / C40 / C21 Defect Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the two lifecycle defects opened by the last two batches' reviews — C41 (re-entrant `initialize()` from a worker thread is a silent cross-pool-free hazard; plus false test-coverage prose shipped in docs) and C40 (`stop()` self-join silently escalates a graceful stop to FATAL_ERROR; `reset()` uses a 100ms sleep as synchronization) — and C21 (RingBuffer double-constructs every element and overclaims "lock-free").

**Architecture:** C41 and C40 share one mechanism: each worker loop publishes its own `std::thread::id` into an atomic member as its first act and clears it as its last (the C36-established pattern); `initialize()`, `stop()`, and `reset()` check those ids FIRST and refuse (log + return false / no-op) when called on a worker thread — the system's lifecycle teardown destroys components a worker's own stack still uses, so refusal is the only honest behavior (`emergencyShutdown` remains the sanctioned from-any-thread path: it stops but never destroys components). `reset()`'s sleep becomes a real wait on `shutdownMutex_` (safe once worker threads are refused). C21 is a two-line deletion plus contract documentation and a TSan SPSC stress test.

**Tech Stack:** C++14, GoogleTest/CTest, ASan/UBSan/TSan sanitizer builds.

## Global Constraints

- **C++14 strictly.** No C++17-isms.
- **Zero-warning policy.** No new dependencies.
- **No sleep-based test synchronization** — poll an atomic against a `steady_clock` deadline; no `condition_variable::wait_for` in tests (GCC 11 libtsan false positives).
- **TSan mandatory for Tasks 1–3** (all touch thread lifecycle or lock-free code). ASan mandatory for Task 1 (the pre-fix hazard is a cross-pool free) and Task 3 (the pre-fix bug is a leak — LSan sees it).
- **Thread-teardown checklist** (3 prior CRITICALs in this codebase — apply to every change here): (1) can a user callback re-enter this? (2) can two threads be inside it at once? (3) does a self-check read state `start()`/`initialize()` writes unsynchronized? — publish ids FROM the worker itself, never compare against `thread_.get_id()`; (4) does the self-check sit behind a lock the joiner holds? — check ids BEFORE taking any mutex; (5) destructor detach fallback for self-destroy; (6) what did any guard you delete also protect?
- Build/test commands (dirs configured; NEVER run conan or cmake configure):
  - `cmake --build build -j$(nproc)` then `ctest --test-dir build --output-on-failure`
  - ASan: `cmake --build build-asan -j$(nproc)` then `ctest --test-dir build-asan --output-on-failure -R <filter>`
  - TSan: `cmake --build build-tsan -j$(nproc)` then `setarch $(uname -m) -R ctest --test-dir build-tsan --output-on-failure -R <filter>`
  - Known flakes (rerun once): `TimingControllerTest.SchedulerPauseAndResume`, `PrecisionTimerTest.PerformanceTest`; TSan perf-threshold tests.
- `clang-format -i` touched files. Defect ID in each commit message. Plan §3 rows use SYMBOL references (no line numbers) + Status paragraph + CHANGELOG in the same commit.

// event-processing thread. Pre-fix, the C39 helper detached the self-handle

### Task 2: C40 — stop() self-join escalation; reset()'s sleep-as-synchronization

**Files:**
- Modify: `src/libs/axonvex_core/src/system.cpp` (`stop` and `reset`)
- Modify: `src/libs/axonvex_core/include/axonvex_core/system.hpp` (doc comments on `stop`/`reset` stating the worker-thread refusal contract)
- Test: `tests/core/systemTest.cpp`

**Interfaces:**
- Consumes: Task 1's `isOnWorkerThread()` and the id-publishing loops.
- Produces: `stop()` called on a worker thread refuses up front (returns false, logs ERROR naming `emergencyShutdown()` as the alternative) BEFORE `transitionState(STOPPING)` — the system stays RUNNING instead of silently escalating to FATAL_ERROR. `reset()` on a worker thread logs ERROR and returns without touching anything. `reset()` on a normal thread replaces its `sleep_for(100ms)` with a real synchronization point: blocking `{ std::lock_guard<std::mutex> wait(shutdownMutex_); }` after its `emergencyShutdown()` call (the destructor's existing idiom) — safe against deadlock precisely because worker threads are refused (a worker blocking on `shutdownMutex_` while an external owner joins that worker was the deadlock shape).

**Defect (plan §3 row C40):** `stop()` from a user event callback reaches `eventProcessingThread_->join()` on itself → `std::system_error(resource_deadlock_would_occur)` → swallowed by `stop()`'s catch → logged "Stop failed" → escalated to `emergencyShutdown()`: a graceful stop silently becomes FATAL_ERROR. Second shape: `reset()` "waits" for an in-flight teardown with `sleep_for(100ms)` before destroying `logger_`/`timingController_` — a guess, not a synchronization point; a teardown slower than 100ms means `reset()` destroys objects the teardown owner is still using.

- [ ] **Step 1: Write the failing tests**

```cpp
// C40 regression: stop() from an event callback self-joined, threw
// resource_deadlock_would_occur into its own catch, and silently escalated a
// graceful stop to FATAL_ERROR. It now refuses up front, before the
// STOPPING transition, so the system stays RUNNING.
TEST_F(AxonVexSystemTest, StopFromEventCallbackIsRefusedWithoutEscalation) {
    EXPECT_TRUE(system_->initialize());

    auto attempted = std::make_shared<std::atomic<bool>>(false);
    auto stopResult = std::make_shared<std::atomic<bool>>(true);
    AxonVexSystem* sys = system_.get();
    system_->registerEventCallback([sys, attempted, stopResult](const SystemEvent&) {
        if (!attempted->exchange(true)) {
            stopResult->store(sys->stop());
        }
    });
    EXPECT_TRUE(system_->start());

    const auto deadline = std::chrono::steady_clock::now() + std::chrono::seconds(10);
    while (!attempted->load() && std::chrono::steady_clock::now() < deadline) {
        std::this_thread::sleep_for(std::chrono::milliseconds(1));
    }
    ASSERT_TRUE(attempted->load());
    EXPECT_FALSE(stopResult->load());
    // Pre-fix the swallowed self-join escalated to FATAL_ERROR; post-fix the
    // refusal happens before the STOPPING transition, so state stays RUNNING.
    EXPECT_EQ(system_->getState(), SystemState::RUNNING);
    EXPECT_TRUE(system_->stop()); // a real stop from outside still works
}
```

### Task 3: C21 — RingBuffer double-constructs every element; overclaims "lock-free"

**Files:**
- Modify: `src/libs/axonvex_core/include/axonvex_core/utils/containers/ringBuffer.hpp` (ctor ~line 178; class doc comment ~line 127)
- Test: `tests/utils/ringBufferTest.cpp` (exists)

**Interfaces:**
- Consumes: nothing from other tasks.
- Produces: no API changes. Ctor no longer placement-news over live elements. Class doc states the honest contract: **SPSC lock-free** (single producer, single consumer) with the memory-ordering argument (acquire on the opposing index, release on own index — the same argument style as `ThreadSafeQueue`, the codebase's good example per project rule 8).

**Defect (plan §3 row C21):** the ctor does `buffer_(std::make_unique<T[]>(capacity_))` — which already value-initializes every element — then loops `new (&buffer_[i]) T{}`: placement-new over a live object ends its lifetime without running its destructor, leaking the original element's resources for any non-trivial T (and the destructor later runs only once per slot, unbalancing ctor/dtor counts). The doc claims generic "lock-free" but the algorithm is SPSC-only: two concurrent writers can both load the same `write_index_` and both store to `buffer_[current_write]`.
