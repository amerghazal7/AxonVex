# C14 / C19 / C39 Defect Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the next three defects from `docs/v1_release_plan.md` §3: C14 (logger `formatString` silently drops every argument; `LOGF_CRITICAL` macro malformed; dishonest perf claim), C19 (PrecisionTimer O(n) sample eviction under mutex, wrong clock, throwing getters), C39 (`initialize()` assigns over potentially-joinable thread handles).

**Architecture:** Three independent single-area fixes. C14 implements the documented `{}`-substitution the API already promises. C19 swaps `high_resolution_clock`→`steady_clock`, converts sample eviction to ring-buffer semantics, and makes the elapsed getters non-throwing (a deliberate, plan-mandated contract change — the old throw is asserted by existing tests, which get updated in the same commit). C39 adds a join-if-joinable helper before the thread-handle assignments in `initialize()`.

**Tech Stack:** C++14, GoogleTest/CTest, ASan/UBSan/TSan sanitizer builds.

## Global Constraints

- **C++14 strictly.** No `std::optional`, `std::filesystem`, structured bindings, `if constexpr`, fold expressions. Variadic recursion is the C++14 way.
- **Zero-warning policy** — new warnings = broken build.
- **No sleep-based test synchronization.** Poll an atomic against a `steady_clock` deadline; no `condition_variable::wait_for` in tests (GCC 11 libtsan false positives).
- **TSan mandatory for Task 3** (thread-handle lifecycle). Tasks 1–2: plain build + full suite + one ASan pass of the touched test binaries.
- **Never add a dependency.** C14's formatting is hand-rolled `{}` substitution, NOT fmt/printf.
- Build/test commands (build dirs already configured, no conan — NEVER run cmake configure):
  - `cmake --build build -j$(nproc)` then `ctest --test-dir build --output-on-failure`
  - ASan: `cmake --build build-asan -j$(nproc)` then `ctest --test-dir build-asan --output-on-failure -R <filter>`
  - TSan: `cmake --build build-tsan -j$(nproc)` then `setarch $(uname -m) -R ctest --test-dir build-tsan --output-on-failure -R <filter>`
  - Known load-sensitive flakes (rerun once): `TimingControllerTest.SchedulerPauseAndResume`, `PrecisionTimerTest.PerformanceTest`; under TSan hardcoded-threshold perf tests may fail from sanitizer overhead.
- `clang-format -i` touched files. Reference the defect ID in each commit message.
- Update `docs/v1_release_plan.md` §3 (row FIXED, **symbol references not line numbers** — line refs rot) + §3 Status paragraph + `CHANGELOG.md`, same commit as each fix. Contract changes (C19 getters) are labeled as behavior changes in the CHANGELOG.

**Interfaces:**

template <typename T, typename... Rest>
inline void Logger::formatImpl(std::ostringstream& stream, const std::string& format, size_t pos,
                               T&& value, Rest&&... rest) {
    const size_t placeholder = format.find("{}", pos);
    if (placeholder == std::string::npos) {
        stream << format.substr(pos); // more args than placeholders: extras ignored
        return;
    }
    stream << format.substr(pos, placeholder - pos) << std::forward<T>(value);
    formatImpl(stream, format, placeholder + 2, std::forward<Rest>(rest)...);
}

template <typename... Args>
inline std::string Logger::formatString(const std::string& format, Args&&... args) {
    std::ostringstream stream;
    formatImpl(stream, format, 0, std::forward<Args>(args)...);
    return stream.str();
}

**Files:**

**Interfaces:**
- Consumes: nothing from other tasks.
- Produces: `PrecisionTimer::ClockType` is `std::chrono::steady_clock` (behavior: `isClockSteady()` now always true). `getElapsedNanoseconds()` (and the seconds/millis/micros wrappers that delegate to it) return `DurationType::zero()` when the timer was never started, instead of throwing — documented at the declaration. Sample eviction is O(1) ring-write; percentile/statistics readers are order-independent (they copy + sort), so retained-set semantics are identical (most recent `max_samples_`).

### Task 3: C39 — `initialize()` assigns over potentially-joinable thread handles

**Files:**
- Modify: `src/libs/axonvex_core/src/system.cpp` (new small private helper + calls before the two `std::make_unique<std::thread>` assignments in `initialize()`)
- Modify: `src/libs/axonvex_core/include/axonvex_core/system.hpp` (helper declaration, private section near the thread members)
- Test: `tests/core/systemTest.cpp`

**Interfaces:**
- Consumes: the thread members `eventProcessingThread_`/`monitoringThread_` and the join discipline established by C33/C36 (self-join guard: never join `this_thread`, exactly as the existing `emergencyShutdown` code does).
- Produces: private `void AxonVexSystem::joinAndClearThreadHandle(std::unique_ptr<std::thread>& handle);` — joins if `handle && handle->joinable() && handle->get_id() != std::this_thread::get_id()`, then `handle.reset()`. Called immediately before EACH thread-handle assignment in `initialize()`.

**Defect (plan §3 row C39):** `initialize()` assigns `std::make_unique<std::thread>` over the handle members unconditionally. Only `stop()`/`emergencyShutdown()` ever join; `cleanupComponents()` does not. If `initialize()` throws after starting a thread, the catch path (`cleanupComponents()` + `transitionState(ERROR)`) leaves joinable threads, and ERROR permits every transition — a retried `initialize()` then assigns over a `unique_ptr<std::thread>` holding a joinable thread → `~std::thread` → `std::terminate`. Second shape, same root: `emergencyShutdown` running ON the event thread skips its self-join (deliberate, C33/C36) and leaves the handle set — the destructor's second pass covers destruction, but nothing covered re-initialization.

**Honesty note (from C8 precedent):** the throw-mid-initialize path has no deterministic test seam (the throw sites are allocation failures). TDD's RED step applies only partially. Do this:
1. Investigate whether the event-callback-initiated e-stop leaves `eventProcessingThread_` joinable at a subsequent `initialize()` assignment on any reachable path (trace `reset()` — its own `emergencyShutdown()` from the caller thread joins the leftover, so the answer may genuinely be "unreachable today without a throw").
2. If you find a reachable pre-fix crash path: reproduce it as a RED test.
3. If not: say so explicitly in the report, add the lifecycle test below as a guard (it exercises the helper's code path and locks the e-stop-from-callback → reset → reinitialize flow), and note the helper is a guard against the throw-retry path.

- [ ] **Step 1: Write the lifecycle test**

```cpp
// C39 guard: an e-stop initiated FROM an event callback runs emergencyShutdown
// on the event thread itself, whose self-join guard (C33/C36) leaves the
// thread handle set. Re-initialization must join-and-clear stale handles
// before assigning new threads over them (~std::thread on a joinable thread
// is std::terminate). The throw-mid-initialize shape of C39 has no
// deterministic seam; this locks the nearest reachable lifecycle.
TEST_F(AxonVexSystemTest, ReinitializeAfterCallbackInitiatedEmergencyShutdown) {
    EXPECT_TRUE(system_->initialize());

    auto fired = std::make_shared<std::atomic<bool>>(false);
    AxonVexSystem* sys = system_.get();
    system_->registerEventCallback([sys, fired](const SystemEvent&) {
        if (!fired->exchange(true)) {
            sys->emergencyShutdown(); // runs on the event thread
        }
    });
    EXPECT_TRUE(system_->start()); // STATE_CHANGE events trigger the callback

    const auto deadline = std::chrono::steady_clock::now() + std::chrono::seconds(10);
    while (system_->getState() != SystemState::FATAL_ERROR &&
           std::chrono::steady_clock::now() < deadline) {
        std::this_thread::sleep_for(std::chrono::milliseconds(1));
    }
    ASSERT_EQ(system_->getState(), SystemState::FATAL_ERROR);

    system_->reset();
    EXPECT_TRUE(system_->initialize()); // must not terminate on a stale handle
    EXPECT_TRUE(system_->start());
    EXPECT_TRUE(system_->stop());
}
```

Definition (system.cpp):

```cpp
void AxonVexSystem::joinAndClearThreadHandle(std::unique_ptr<std::thread>& handle) {
    if (handle && handle->joinable() && handle->get_id() != std::this_thread::get_id()) {
        handle->join();
    }
    handle.reset();
}
```

In `initialize()`, immediately before each of the two thread assignments:

```cpp
        joinAndClearThreadHandle(monitoringThread_);
        // ... existing: monitoringThread_ = std::make_unique<std::thread>(...);
```

```cpp
        joinAndClearThreadHandle(eventProcessingThread_);
        // ... existing: eventProcessingThread_ = std::make_unique<std::thread>(...);
```

CAUTION — ordering vs the C38 flag-clear: `initialize()` currently clears `isShuttingDown_` (and then sets `monitoringEnabled_`/`eventProcessingRunning_` true) around these assignment sites. A stale thread's loop must remain guaranteed-exiting at the moment you join it: join the stale handles BEFORE clearing/setting any of the three flags, or a stale loop could observe revived flags and stop exiting (the `currentState_ >= STOPPING` guard would still end it only if state is FATAL_ERROR — do not rely on that here). If you must reorder, land: join both handles → clear `isShuttingDown_` → set per-thread run flags → start threads, and document why in the code and your report.
