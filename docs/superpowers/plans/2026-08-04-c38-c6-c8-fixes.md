# C38 / C6 / C8 Defect Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the next three defects from `docs/v1_release_plan.md` §3: C38 (stale `isShuttingDown_` kills the event pipeline after reset+reinitialize), C6 (declared-but-unimplemented public API), C8 (`ProcessingUnit` advertises movability it cannot deliver).

**Tech Stack:** C++14, GoogleTest/CTest, ASan/UBSan/TSan sanitizer builds.

  - Known load-sensitive flakes (rerun once before believing a failure): `TimingControllerTest.SchedulerPauseAndResume`, `PrecisionTimerTest.PerformanceTest`; under TSan, hardcoded-threshold perf tests may fail from sanitizer overhead.
- `clang-format -i` touched files before committing. Reference the defect ID in each commit message.

- Update `docs/v1_release_plan.md` §3 (mark the defect FIXED, same row style as C29/C37) and `CHANGELOG.md` in the same commit as each fix. C6 and C8 are **breaking API changes** — say so in the CHANGELOG entry (precedent: C29/C31 removals).

### Task 1: C38 — stale `isShuttingDown_` leaves a re-initialized system with a dead event pipeline

**Files:**
- Modify: `src/libs/axonvex_core/src/system.cpp` (`initialize(const std::string&)`, ~line 198 region — the clear goes immediately before the event/monitoring threads start)
- Test: `tests/core/systemTest.cpp` (fixture `AxonVexSystemTest` exists)

**Interfaces:**
- Consumes: `AxonVexSystem::initialize/start/stop/reset`, `registerEventCallback(EventCallback)` (system.hpp:498, `EventCallback = std::function<void(const SystemEvent&)>`, system.hpp:218).
- Produces: no signature changes. New contract: `initialize()` is the single owner of clearing `isShuttingDown_`; after reset()+initialize(), the event pipeline is alive (publishEvent enqueues, eventProcessingLoop runs).

**Defect (plan §3 row C38):** `isShuttingDown_` (system.hpp:773) is set by `stop()`/`emergencyShutdown()` and never cleared. `reset()` returns the state machine to UNINITIALIZED with the flag still true; a subsequent `initialize()` starts an event thread whose loop guard `while (eventProcessingRunning_.load() && !isShuttingDown_.load())` (system.cpp:~1419) exits immediately, and `publishEvent` (system.cpp:~1393) silently drops every event. Healthy-looking system, dead event pipeline — the banned silent-failure shape.

- [ ] **Step 1: Write the failing test**

Append to `tests/core/systemTest.cpp`:

```cpp
// C38 regression: isShuttingDown_ (set by stop/emergencyShutdown) was never
// cleared, so a system re-initialized after reset() had a dead event pipeline:
// eventProcessingLoop's guard saw the stale flag and exited immediately, and
// publishEvent dropped every event — with the state machine reporting healthy.
TEST_F(AxonVexSystemTest, EventPipelineIsAliveAfterResetAndReinitialize) {
    EXPECT_TRUE(system_->initialize());
    EXPECT_TRUE(system_->start());
    EXPECT_TRUE(system_->stop());
    system_->reset();

    EXPECT_TRUE(system_->initialize());
    auto sawEvent = std::make_shared<std::atomic<bool>>(false);
    system_->registerEventCallback(
        [sawEvent](const SystemEvent&) { sawEvent->store(true); });
    EXPECT_TRUE(system_->start()); // publishes STATE_CHANGE events

    const auto deadline = std::chrono::steady_clock::now() + std::chrono::seconds(5);
    while (!sawEvent->load() && std::chrono::steady_clock::now() < deadline) {
        std::this_thread::sleep_for(std::chrono::milliseconds(1));
    }
    EXPECT_TRUE(sawEvent->load()) << "re-initialized system's event pipeline is dead";
    EXPECT_TRUE(system_->stop());
}
```

- [ ] **Step 2: Run it, verify it fails**

```bash
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure -R "EventPipelineIsAlive"
```

Expected: FAIL on `sawEvent` after the 5s deadline (pre-fix, publishEvent drops everything once the stale flag is set).

- [ ] **Step 3: Clear the flag in `initialize()` — the single owner**

In `initialize(const std::string&)`, immediately before the monitoring/event threads are started (after `initializeBlocksLayout()` succeeds, before `if (systemConfig_.enablePerformanceMonitoring)`):

```cpp
        // C38: initialize() is the single owner of clearing the shutdown
        // latch. stop()/emergencyShutdown() set it; nothing else may clear
        // it. Cleared here, immediately before the threads that read it
        // start, so a racing e-stop that re-sets it wins (its flags end the
        // fresh threads' loops, which is the correct outcome).
        isShuttingDown_.store(false);
```

Do NOT also clear it in `reset()` — two clearers would let a racing `stop()` be un-done by the other one.

- [ ] **Step 4: Verify — focused test, then full suite + TSan**

```bash
ctest --test-dir build --output-on-failure -R "EventPipelineIsAlive"
cmake --build build -j$(nproc) && ctest --test-dir build --output-on-failure
cmake --build build-tsan -j$(nproc) && setarch $(uname -m) -R ctest --test-dir build-tsan --output-on-failure -R "AxonVexSystemTest"
```

Expected: all green, zero TSan reports.

- [ ] **Step 5: Docs + commit**

Flip C38 to FIXED in plan §3 (row style like C37: root cause, fix, verification) and update the §3 Status paragraph. CHANGELOG entry. Also correct the C38 row's stale reference `system.hpp:762` → the member's current line (it's at system.hpp:773; verify before writing) — a deferred nit from the last review wave. `clang-format -i` touched files.

### Task 3: C8 — ProcessingUnit's advertised movability is a lie; make non-movability explicit

**Files:**
- Modify: `src/libs/axonvex_core/include/axonvex_core/processingUnit.hpp:68-70` (the `// Non-copyable, movable` comment and the two `= default` move declarations)
- Test: `tests/core/processingUnitTest.cpp` (add compile-time contract asserts)

**Interfaces:**
- Consumes: nothing from earlier tasks.
- Produces: `ProcessingUnit` is explicitly non-movable (`= delete`). No runtime behavior change — the `= default` moves were already *defined as deleted* by the compiler (two `std::mutex` members are non-movable), so no code can have been moving these objects (verified 2026-08-04: the only `std::move` uses near ProcessingUnit are `unique_ptr` moves, which are unaffected).

**Defect (plan §3 row C8):** `processingUnit.hpp:69-70` declares `ProcessingUnit(ProcessingUnit&&) = default;` and the matching assignment under a `// Non-copyable, movable` comment, while the class owns `portsMutex_`/`statsMutex_` (both `std::mutex`) and hands out raw `BasePort*` from `ownedPorts_` — plus the system and ports hold stable pointers to the unit. The `= default` moves are silently defined-as-deleted, so the header advertises a movability that (a) doesn't exist and (b) must never exist, or every raw pointer dangles. Rule #6: delete the move ops, don't `= default` them.

- [ ] **Step 1: Make the contract explicit**

Replace processingUnit.hpp:68-70:

```cpp
    // Non-copyable, non-movable: the unit owns two mutexes (moves would be
    // defined-as-deleted anyway) and ports/system hold stable raw pointers
    // to it — relocation would dangle them (C8).
    ProcessingUnit(const ProcessingUnit&) = delete;
    ProcessingUnit& operator=(const ProcessingUnit&) = delete;
    ProcessingUnit(ProcessingUnit&&) = delete;
    ProcessingUnit& operator=(ProcessingUnit&&) = delete;
```

- [ ] **Step 2: Add the compile-time regression**

In `tests/core/processingUnitTest.cpp` (file scope, near the top after includes; add `#include <type_traits>` if absent):

```cpp
// C8: ProcessingUnit must stay non-movable — ports and the system hold raw
// pointers to it with a stable-reference contract. These asserts lock that
// in at compile time (the old '= default' moves were silently deleted; these
// fail loudly if anyone tries to reintroduce movability).
static_assert(!std::is_move_constructible<axonvex::core::ProcessingUnit>::value,
              "ProcessingUnit is non-movable: ports/system hold raw pointers to it (C8)");
static_assert(!std::is_move_assignable<axonvex::core::ProcessingUnit>::value,
              "ProcessingUnit is non-movable: ports/system hold raw pointers to it (C8)");
static_assert(!std::is_copy_constructible<axonvex::core::ProcessingUnit>::value,
              "ProcessingUnit is non-copyable (C8)");
```

Note honestly in your report: these asserts pass pre-fix too (the `= default` moves were already deleted-in-effect), so this is a contract lock, not a discriminating regression test — the discriminating check for C8 is the header no longer lying. TDD's RED step does not apply.
